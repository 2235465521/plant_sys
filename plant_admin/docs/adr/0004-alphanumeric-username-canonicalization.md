# 0004. 控制台用户名规范与小写归一化

控制台登录与注册用户名严格限定为 2~32 位纯英文字母与数字组合（正则 `^[a-zA-Z0-9]{2,32}$`），并在前后端双层统一归一化转换为全小写。

## 背景与原因

此前系统对用户名无严格字符集限制，导致历史数据中出现下划线（如 `test_admin`）与非 ASCII 字符；同时 MySQL 默认 `utf8mb4_unicode_ci` 排序规则大小写不敏感，若用户分别输入 `Admin` 与 `admin` 极易引发展示歧义及唯一索引冲突。通过统一限制字符集为 `[a-z0-9]` 并执行小写归一化，既杜绝特殊字符注入与展示异常，又保证注册与登录逻辑强一致性。

## 决议内容

1. **字符集与长度限制**：仅允许英文字母与阿拉伯数字，长度限定在 2 至 32 位字符之间。
2. **归一化策略**：前端输入与后端接口在处理前均自动 `.strip().toLowerCase()`，入库与 Token 签发统一采用全小写。
3. **校验防御**：前端表单即时正则反馈；后端 Pydantic `LoginRequest` 与 `RegisterRequest` 双重防御拦截；CLI 建号工具同步校验。
4. **历史账号清洗**：将已有测试账号 `test_admin` 重命名为 `testadmin`，并停用异常字符测试记录。
5. **配套安全增强**：为避免注册默认密码 `zkbz2026` 无法变更的安全隐患，同步上线个人“修改密码”接口与弹窗。
